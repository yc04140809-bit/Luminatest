# セキリュウガ戦後＋序盤UX改善（App、2026-10-07）

指示書「セキリュウガ戦後＋序盤UX改善」の実装内容。既存の四択・TIME SHIFT・WORLD MEMORY 本体・ガルドイベント本編・既存セーブ互換・既存戦闘演出・既存探索仕様には手を入れていない。

## P0：酒場の初訪問イベントの順序

**会話キュー**（`mugen-core/core/talk/talkQueue.ts`）を作った。NPC が「いま話すべきこと」を優先順位の高い順に 1 回の会話（sitting）で続けて話し、2 つ目以降は「区切り（bridge）」の台詞から始める。今後の NPC にもそのまま使える。

| 優先 | id | 条件 | 自動開始 | 区切り |
|---|---|---|---|---|
| 100 | `GRAVE_MEETING`（初対面） | このセッションでまだ話していない | しない（単独なら「話す」で） | — |
| 50 | `GRAVE_SEKIRYUGA_STORY`（セキリュウガの話） | 噂を聞いた（`RUMOR`） | する | グラスを拭く手を止めずに、ふと顔を上げた。／「そういや……お前ら、遺跡の話は聞いたか？」 |
| 40 | `GRAVE_AFTER_SEKIRYUGA`（戦闘後） | 戦闘後を見終えた（`SETTLED`）で未聴 | する | 「……で。遺跡、行ってきたんだろ。」 |

- 酒場に入った時に「自動開始」の会話があれば、初対面（まだなら）→ 区切り → 本題 の順で再生する。
- 初対面だけの時は従来どおり「話す」で始まる。マスター本人の噂から始まった場合も従来どおり（区切りなしでそのまま本題）。
- 定義：`mugen-core/content/talk/graveTalks.ts`（初対面の台詞だけは App 側の描写差し替えがあるため App が追加）。
- 酒場の UI・配置・背景・立ち絵は変更なし。

## P1：主人公の初期スキル《瞬断》（仮名称）

| 項目 | 内容 |
|---|---|
| 威力 | 通常攻撃の 2.0 倍（同じ計算式に倍率を 1 つ足すだけ） |
| クールダウン | 3（使ったターンを含めて 3 ターンに 1 回。表示「あと N ターン」） |
| MP | 消費なし |
| 習得 | 最初から（`HERO_STARTING_SKILLS`） |
| 演出 | 通常攻撃と同じ踏み込み・振りに、青白い剣閃と、遅れて交差する 2 本目の斬線 |
| SE | `battle_skill_slash`（`battle_attack_slash` を低く重く借用） |
| 場所 | 戦闘の「スキル」の中（これまで空だった欄）。NEW は最初に使った時に消える |

戦闘時間への影響（2000 戦の実測、使えるたびに使う）：モスラビット 12.2 → 9.4 ターン、ガルド 21.2 → 16.1、セキリュウガは HP を 150 → 170 にして約 12 ターン（`docs/SEKIRYUGA_ROUTE.md`）。モスラビットとガルドの数値は変えていない。

- コア：`playerSkill`・`skillReadyIn`（`battleLogic.ts`）。スキルを使わない戦闘は、乱数の使い方も状態の形も以前と同じ（テストで確認）。Artifact は変更なし。

## P1：AUTO 戦闘の解禁

- ガルド戦が終わるまで（四択が決まるまで）AUTO ボタンは出ない。ガルド戦そのものにも出ない。
- 四択と TIME SHIFT の後、村に戻った時に 1 回だけ「AUTO戦闘が使用可能になりました。」（約 3 秒、自動で消える）。
- AUTO の判断はコアの既存 AUTO（`decideTurn`、Artifact と同じ）。加えて、ボスが咆哮で溜めている時は防御、《瞬断》が使える時は通常攻撃の代わりに《瞬断》。
- ×2 は変更なし。

## P1：BOSS 専用スキルカットイン

- 敵データに任意の「大技」（`EnemyMoveSet.signature`）を追加：指定 HP 以下になった最初のターンに 1 回だけ使う。
- App 側の表（`ui/battle/cutin/bossCutIn.ts`）に載っているボスだけ、その大技でカットインを出す。通常攻撃・通常スキルでは出ない。
- 再生順：主人公の行動 → 画面がほぼ暗転してボスのカットイン（技名・ボスの姿）→ 技の発動 → 氷の演出（`bp-frost`）と氷の SE（`battle_magic_ice`）。
- セキリュウガ：《氷晶咆哮》（HP 50% 以下で初回、爪撃 ×1.8、全体攻撃）。
- カットインのテーマ `boss`（`cutin.css`）を追加。

## P2：共通 NEW 通知

- **既読の記録は 1 行**（world_state `readMarks`、`core/world/readMarks.ts`）。`種類:id` の一覧で、行が無い古いセーブは「何も読んでいない」として読める。SAVE_VERSION は 3 のまま、移行なし。WORLD MEMORY ではない。
- **メニューを開いただけでは消さない**。その中の新しいもの自体を見た・使った・読んだ時に既読にする。
- 部品：`ui/common/NewBadge.tsx`（赤地に白文字、明るい縁で背景を問わず読める）、`ui/common/OnceNotice.tsx`（1 回だけの短い通知）。

| 対象 | NEW が出る場所 | 既読になる時 | id |
|---|---|---|---|
| 噂 | 村「噂話」／各噂の行 | その噂をタップして開いた時 | `rumor:<id>` |
| 目的地 | 村「探索する」／地方図「古代遺跡」／「遺跡の奥へ進む」 | その目的地を触った時 | `dest:<id>` |
| スキル | 戦闘「スキル」／《瞬断》の行 | 使った時 | `skill:<id>` |
| 装備（見つけた物） | 村「ステータス」／ステータス「装備」／武器の欄／一覧の行 | その武器が並ぶ一覧を開いた時（名前と性能が見える＝確認） | `equip:<id>` |
| WORLD MEMORY | 村「世界の記憶」／各記録の行 | その記録をタップした時 | `memory:<id>` |
| 1 回だけの通知 | （通知そのもの） | 表示された時 | `note:<id>` |
| 1 回だけの会話 | — | 最後まで聞いた時 | `talk:<id>` |

人物情報・ストーリーの NEW は、同じ部品と同じ記録で追加できる（今回は対象画面がまだ無い）。
