## 1. 指示書について：良かったところ

1. **「今回触らないもの」が毎回書かれている。** 実装の範囲が広がらず、既存の正常な機能を壊さずに済んでいる。一番効いている書き方。
2. **確認項目が番号付きで具体的。** 「100% → 80% → 60%」「844×390 / 640×300」など、数字と画面サイズがあるので、テストで固定できた。
3. **PoC を1面で試してから広げる進め方。** 草原 → 森・遺跡、パン屋ルート → 5ルート。手戻りが小さい。
4. **思想が書かれている。** 「人生は攻略できない」「善＝得にしない」「数値を見せない」。細かい判断（マーカーを控えめにする、関係を数値で出さない）が、思想から自然に決まる。

## 2. 指示書について：改善できるところ

### 2-1. 素材の規格を、生成の時点で渡す（最優先・すぐ効く）

10/18〜19 の探索キャラでは、歩きの絵が 3 回やり直しになった（頭身が違う／瞳が左右逆／背景が白）。
原因は絵の出来ではなく、**規格が生成の側に伝わっていないこと**。次のような「素材発注シート」を1枚作り、毎回そのまま生成に添えることを提案する。

```
【探索キャラ素材の規格】
- 4方向（前・後ろ・左・右）× 立ち1＋歩き4。立ちと歩きを1枚のシートで一緒に描く（頭身がそろう）
- 背景透過 PNG。光・輪・影を描き込まない
- 全コマ同じ大きさの枠、同じ接地点、同じ頭身（頭の幅を全コマそろえる）
- 反転で作らない。左向き＝本人の左側が見える
  ・主人公：赤い線は左目の下 → 左向き・前向きでだけ見える
  ・ケイオス：右目＝金、左目＝青。左向き＝青い瞳・黒い翼が手前／右向き＝金の瞳・白い翼が手前
- 色・服・飾りは基準シート（添付）と同じ
```

- 同じ考え方で「戦闘用」「立ち絵（会話）」「背景（通常＋グリッド）」「エフェクト」のシートも作れる。
- 瞳と翼の左右は、今回の修正版4面図でも横向きが逆だった。**キャラごとの左右ルールを1か所（`docs/PORTRAIT_MASTER.md` など）に書いて、毎回そこを参照する**のが確実。

### 2-2. PoC の「採用／不採用」をまとめて決める日を作る

今、判断待ちの PoC がたまっている。

| PoC | 状態 |
|---|---|
| 遺跡の歩行範囲（緑・黄・赤・青） | 承認待ち（`EXPLORATION_AREAS.md` §4） |
| 草原の発見演出・遠近・縦カメラ・環境演出 | 確認待ち（`EXPLORATION_DISCOVERY.md` §6） |
| 発見演出の森・遺跡への展開 | 草原の判断待ち |
| ガルド・パン屋ルート | PoC のまま |
| 「！」と発見マークの共存 | 本編と PoC で2方式が並んでいる |

PoC が並ぶほど、テスト・資料・頭の中の負担が増える。**「採用して本編へ」「保留」「やめる」を一覧で一度に決める**と、TIGS までの道がはっきりする。
おすすめは、草原の発見演出と遺跡の歩行範囲は**採用して本編へ**（どちらも実機で操作感の問題が出ていない）。

### 2-3. 各指示書に「TIGS の試遊のどこに効くか」を1行書く

最近の指示書は、見た目と手触りの改善が中心で、どれも質は上がっている。
ただ、TIGS で試遊者が触るのは**最初の 10〜15 分**。その時間に出ない画面（ステータスの細部、酒場の交換、後半の演出など）の磨き込みは、後回しにできる。
「この指示書は試遊の◯分目に効く／効かない」を1行書くだけで、優先順位がぶれにくくなる。

### 2-4. 仮のまま残っているものを一覧にする

- 発見の SE 5 種（戦闘音を借りた仮の音）
- 草原の WORLD MEMORY 地点（仕組みはあるが置いていない）
- ガルド 4 ルート（治療所・衛兵・見逃し・死亡）の 3 年後
- 襲撃後の村の背景、復興の BGM

仮のものは、出す前に「仮のまま出す」か「差し替える」かを決める必要がある。一覧があれば、素材の発注もまとめてできる。

## 3. TIGS に向けた提案

### 3-1. 「試遊の道筋」を1本に絞る（最重要）

TIGS の試遊は、1人あたり 10〜15 分程度が現実的。第1章をそのまま出すと、テーマに届く前に交代になる。
各資料の「TIGS 用最小完成形」（`GALD_FIVE_ROUTES.md`）は、もう答えを持っている。

```
導入（漫画の冒頭）→ 村（短く）→ 探索（草原 or 森）→ ガルド戦 → 四択
→ TIME SHIFT → 3 年後：選んだ道の先で、ガルドと周りの人がどうなったか → 終わりの1枚
```

- **到達目標**：15 分以内に「四択 → 3 年後の変化」まで行く。10/10 のレビューの時点で四択まで 15〜20 分だったので、村と探索を短くした試遊用の道筋が要る。
- **四択の5つの道**：今はパン屋ルートだけ PoC。試遊で他の答えを選ぶ人もいるので、**残り4つも「3年後の1場面」だけは用意する**（全部を高品質にしなくていい。最低限、選んだ答えが無視されないこと）。
- **終わりの1枚**：「あなたが見たのは、この人の人生の一つの可能性です。」（資料の言葉そのまま）＋ ウィッシュリストや SNS の QR。

### 3-2. 展示モードを作る

ブースでは、作者がいない時間も試遊が回る必要がある。

| 機能 | 中身 |
|---|---|
| 試遊開始 | タイトルに「試遊をはじめる」。押すたびにセーブを初期化して、試遊の道筋から始まる |
| 無操作で戻る | 一定時間（例：90 秒）触られなければ、確認を出してタイトルへ |
| 名前入力 | 決まった名前で飛ばす（ブースで文字入力は時間を食う） |
| DEBUG の入口 | 出さない（リリース用ビルドの扱い。今も自動チェックがある） |
| 選択の記録 | 端末の中だけで「この端末で選ばれた答え」を数える。ブースの説明やSNSで「今日はパン屋へ連れて行った人が◯割」と話せる（試遊者には他の答えを見せない） |
| 音 | ヘッドホン前提の音量。会場の音でも聞こえる大きさの SE |

小さく作れる（ゲーム本体はそのまま、入口と後始末だけ足す）。

### 3-3. 「人生は攻略できない」を、ブースで伝える仕掛け

- 試遊者同士の会話が一番の宣伝になる。「どれを選んだ？」と隣の人と話せるように、**四択の画面をブースの紙にも載せる**（結果は載せない）。
- 2 台並べられるなら、**同じ場面から違う答えを選んだ2人が、3年後に違う村を見る**のが一番伝わる。
- 展示パネルの文言は資料にもう良いものがある（`HIDDEN_SEED_SYSTEM.md` §27–28、`OFF_SCREEN_LIFE_SYSTEM.md` §30–31）。

### 3-4. 最初の3分を磨く

試遊者が残るかどうかは、最初の3分で決まる。この順に磨くのを提案する。

1. 漫画形式の導入（もうある）→ 村に入るまでの間の取り方
2. 最初の探索：草原の PoC（遠近・発見演出・環境演出・新しいミニスタチュー）を**本編に採用**して、ここで見せる
3. 最初の戦闘の手触り（ヒットストップ・カメラ・特殊演出はもうある）

### 3-5. 素材を軽くする（APK 約 420MB → 推定 100〜150MB）

- 素材の 8 割が PNG。探索・エフェクトで使った WebP に変換すると、見た目をほぼ変えずに大きく減らせる（推定。変換して実測する）。
- 効くところ：
  - 展示端末へのインストールと更新が速くなる。
  - テスターに配りやすくなる。
  - 将来の Steam・ストア配信でも必要になる。
- 作業はファイルの変換と参照の置き換えで、ゲームの動きは変えない。テストでそのまま確認できる。

### 3-6. 英語

TIGS は海外のメディアや来場者も多い。全部の翻訳は重いので、段階を分ける。

1. **展示パネル・チラシ・Steam ページは英語も用意する**（小さい）
2. **試遊の道筋の文章だけ英語字幕**を入れる（中。文章の量を数えてから判断）
3. 本編の翻訳は後

### 3-7. 実機とブースの準備

- 展示する端末（タブレット推奨。横画面が広い）で、試遊の道筋を通しで 20 回以上遊び、熱・電池・音を確かめる。
- 展示用ビルドを固定して、当日は更新しない（テスター版 APK の仕組みがそのまま使える）。
- 感想の回収：テスター用の Google フォーム案（`TESTER_GUIDE.md` §5）を、ブース用に3問程度へ縮めて QR で。
- 試遊の道筋を通す e2e を1本足し、**15 分以内に終わるか**を時間で確かめる（今の e2e の仕組みで書ける）。

### 3-8. 宣伝の材料

- 30〜60 秒の動画：①四択 ②TIME SHIFT ③3 年後の変化 ④グレイヴの豪断・主人公の零閃・ケイオスの翼。
  - 演出見本（`?preview=fx`）があるので撮りやすい。
- Steam のストアページとウィッシュリストは、TIGS より前に出しておくのが一番安い認知の手段（`PRODUCT_STRATEGY.md` §5）。
- note の小説との導線：ブースのチラシに「この世界の物語」として QR を1つ。
