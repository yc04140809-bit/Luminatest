# App版 戦闘画面 — Artifact戦闘画面の再現

状態（2026-09-26）：**本編の戦闘に接続済み。** 実際の戦闘（森のモスラビット戦・ガルド戦）は
この画面で行われる。カットイン・個別スキル演出・ケイオス介入・逃走・AUTO は未実装（次の工程）。

## 本編接続（2026-09-26）

- `mugen-app/src/ui/battle.tsx` の `BattleScreen` は、**戦闘の進め方はそのまま**
  （共通部分の `playerAttack` / `playerDefend` / `castMagic` / `useItem`、アイテム消費の保存、
  ケイオス覚醒、勝敗の受け渡し）で、表示だけを `BattleStage` に置き換えた。
- ターンの見せ方は `src/ui/battle/battleTheatre.ts`（Artifactと同じ順番・同じ時間）：
  攻撃 → 踏み込み（カメラ）→ 命中・当たり光 → **本物のダメージ数字**（行動前後の敵HPの差）→
  敵の反応 → 敵の反撃（数字は共通部分の `lastEnemyDamage`）。
  時間の数値は Artifact のソースから読み取るテストで一致を固定。
- 倒したとき：ノックダウン（340ms）→ 倒れた絵 → 1.9秒後に既存の流れ（戦闘結果・ガルドの四択）へ。
  負けたとき：1.2秒後に既存の流れ（村で回復）へ。
- ×1 / ×2：戦闘ごとに×1から（Artifactと同じ。端末には保存しない）。×2でも各動きに最低時間あり。
- 連打：演出中は押しても次のターンにならない（見た目は変えず、`data-locked` で判定）。
  Artifactは演出中に押すと前の演出を打ち切って次を始めるが、重なりを防ぐためApp版は待たせる。
- 画面を離れる／アプリを閉じると、演出のタイマーは全部止まる。

### Artifactとの意図的な違い
1. **倒した一撃に、存在しない反撃が出ない。** 共通部分は、敵を倒した行動では前のターンの
   「敵の行動・ダメージ」をそのまま残す。Artifactの画面はそれを読んで、倒した直後に
   前のターンと同じ反撃（数字つき）を再生してしまう。App版は「倒されたら反撃していない」として
   出さない（共通部分は変更していない。表示側の判断のみ）。
2. **演出中の連打は無視**（上記）。
3. **魔法**：STEP C で本編に接続済み（下の「ケイオス魔法の演出と本編接続」）。Artifact の魔法は
   詠唱の絵と敵の反応だけだが、App 版はカットイン・オーラ・着弾まで出す。
4. **AUTO・逃走のチップは出さない**（次の工程）。×2は使える。
5. **《ケイオスの守護》などの介入なし**、アルカナの観測記録なし（App版の戦闘には無い仕組み）。

## 選択パネルは最前面（2026-09-26）

戦闘中に開く「選ぶための画面」（魔法・スキル・アイテム、今後の対象選択やサブメニュー）は
`src/ui/battle/BattlePicker.tsx` の層に描く。重なり順（奥 → 手前）：

1. 戦闘背景
2. 敵・味方の立ち絵（敵のHP札を含む）
3. 通常のHUD・コマンド列
4. （ケイオス覚醒の場面）
5. **選択パネル**（半透明の暗幕＋パネル）— 最前面

- Artifactではトレイがコマンド列の中にあり、立ち絵（剣・翼）や敵のHP札の**後ろ**に回っていた。
  App版はトレイの中身（`MagicTray` / `ItemTray`、Artifactと同一ファイル）はそのまま、置き場所だけ変えた。
- 暗幕は背面を暗くするだけで、背景・キャラクターは見えたまま。
- 暗幕が画面全体の押下を受けるので、パネル表示中は攻撃・防御・×2・BGMなど**背面のボタンは押せない**。
  暗幕を押すと「戻る」（パネルが閉じるだけで、ターンは進まない）。各パネルの「やめる」も同じ。
- パネルはコマンド列の上（下から78px、Artifactと同じ）から画面上端の手前まで。入りきらないときはパネル内でスクロール。
- 今後、選択が必要な画面を足すときは `BattlePicker` で包めば同じ順番・同じ操作になる。
- **魔法欄のMPの読みやすさ（実機確認を受けて）**：Artifactの行は「白→12%の金」のぼかしで、暗いパネルの上では
  行の中ほど（MPの位置）が灰色になり、金色のMPが約1.2:1のコントラストしかなかった。
  選択パネル内だけ、行を「白→薄い砂色」の不透明に、MPを同じ系統の濃い金（太字・12px）にして
  6:1以上にした。配置・文言・大きさの構成は変えていない（`battle.layers.css`）。
- 確認：`e2e/battlePicker.spec.ts`（5機種サイズ×3パネルで、各行の名前・MP・「やめる」の位置に指を置くと
  パネルに当たること、背面のボタンに当たらないこと、実戦闘で背面の攻撃位置を押してもターンが進まないこと）、
  `e2e/gald.spec.ts`（ガルド戦の魔法パネルで同じ確認）。

## 主人公の通常攻撃の強化（STEP D ＋ ロードマップ STEP 3、2026-09-26）— **本編に接続済み**

v18 の通常攻撃（接近・振りかぶり・大きな剣の軌跡・斬った瞬間・帰還）を、主人公の《攻撃》に足した。
Android 実機確認 OK（STEP 4）を受けて、本編の `BattleScreen` で `useBattleTheatre(speed, { slash: true })`
に接続した。DEBUG プレビューでは「剣の軌跡：なし」で以前の攻撃と見比べられる。

- **部品**：`src/ui/battle/slash/`
  - `SwordSlash.tsx` + `slash.css`：v18 `.sword-arc`（明るい外縁・金の内縁・光の筋の三日月）を、
    主人公側（右上）から敵の体を斜めに横切るように振り下ろす軌跡として描く。刃が届く瞬間に v18 `.hit-effect`
    （閃光・輪・一本の斬り筋）。
  - `slashTiming.ts`：軌跡 0.34秒・斬り 0.42秒（×2 は 0.24秒・0.30秒が下限）。
- **流れ（STEP 3 で v18 `playAttack()` の動きを移植）**：
  **接近**（敵の前まで歩く）→ **振りかぶり** → **振り下ろし＋軌跡** → 刃が届く瞬間（振りの40%）に
  **斬り**＋既存の当たり光・**本物のダメージ数字**・敵の被弾リアクション → **構えを戻す** → **帰還**（元の位置へ）
  → 敵の反撃（主人公が戻ってから）→ 撃破時は既存どおりダウン。
  - 立ち位置は v18 の `travelToEnemy()` と同じ式：主人公の左端が「敵の右端＋画面幅の7.5%」で止まり、
    足元は敵の地面の高さへ（最低でも画面幅の24%は歩く）。実際の絵の位置を測るので、モスラビットでもガルドでも
    敵に重ならず、剣だけが届く。
  - 振りの傾き（振りかぶり 5°→ 当たり −11°→ 振り抜き −6°）も v18 の値。攻撃専用の絵は無いので、
    v18 と同じく `hero-battle-idle.png` を動かして見せる。
  - 時間（`slash/slashTiming.ts` の `REACH_MS`、v18 の約8割）：接近0.34・振りかぶり0.13・振り0.24・
    当たりの間0.15・戻し0.12・帰還0.34秒 ＝ ×1 約1.3秒／×2 約0.8秒（各段に下限あり、振りは v18 と同じ 0.24秒）。
  - この形では Artifact の小さな踏み込み（`.strike`）とカメラの寄りは使わない（実際に歩くため）。
- **出る時だけ**：主人公の《攻撃》だけ（`battleTheatre.playTurn` の ATTACK）。魔法・アイテム・防御・
  敵の攻撃には出ない（テストで確認）。
- **重なり順**：敵の絵の中（カメラの寄りや被弾の揺れと一緒に動く）に描き、ダメージ数字（HitFx）はその上、
  HUD（TURN ORDER・敵HP枠以外のコーナー・コマンド）はさらに上。**斬撃で文字が隠れない／数字が斬撃の後ろに
  隠れない**を優先した配置（指示の「HUD→斬撃→数字」に対し、斬撃を HUD の下にして文字の可読性を守る）。
- **大きさ**：画面の高さに対する割合なので、遠くのモスラビットでも近くのガルドでも同じ剣の届き方に見える。
- **通常攻撃らしさ**：暗転・カットイン・画面フラッシュなし。約0.3〜0.5秒で消える。
- 戦闘計算・攻撃力・敵HP・命中・撃破条件・SAVE・WORLD MEMORY は変更していない。数字は従来どおり
  「攻撃前の敵HP − 攻撃後の敵HP」。
- **DEBUGプレビュー**：「主人公の通常攻撃」欄に「⚔ 通常攻撃を1回（新しい戦闘で）」と
  「剣の軌跡：あり（強化）／なし（今の本編）」の切り替え。下の「攻撃」ボタンでも同じ演出で倒すまで戦える。
  `&swing=1`（開いた直後に1回）、`&slash=0`（強化なし）。
- **確認**：`slash/slashTiming.test.ts`、`e2e/slash.spec.ts`（軌跡が敵の上に出る・振りの拍で始まる・
  敵の攻撃が当たる前に消える・数字＝HP減少量・×2 で短いが 0.28秒以上・魔法/アイテム/防御では出ない・
  切り替えで消える・撃破まで・背景6種・同じ操作で同じ数字・**本編ではまだ出ない**）。

## レヴィ「幻影槍6本」（ロードマップ STEP 5、2026-09-26）— **DEBUGプレビューのみ・本編未接続**

v18 の レヴィ技（`playLeviSkill()`・`.levi-*`）を、**演出部品**として App に作り直した。本編の技・コマンドには
つないでいない（正式技との接続は後の段階）。デバッグビルドの戦闘演出プレビューからだけ再生できる。

- **流れ**：（カットイン：v18 見本「冥槍・黒葬封界」仮称。切り替えで省略可）→ レヴィが主人公の位置に入る
  （主人公は一歩引いて見えなくなる。v18 `is-suppressed`）→ **構え**（沈んで冥い光を溜める）→
  **幻影槍6本が1本ずつ出現**（敵を囲む6方向に、穂先を敵へ向けて浮かぶ）→ **6本が順番に刺さる**
  （1本ごとに刺さった光と敵の揺れ）→ 一拍 → **フィニッシュ**：レヴィ自身が槍で突進（残像・槍の軌跡）→
  白い閃光・十字の光・封印の輪・破片、刺さっていた6本が砕ける、画面が少し揺れる → レヴィが消え、主人公が戻る。
- **連続感**：v18 は6本を 0.078秒間隔で一斉に近く撃っていたが、ここでは **0.12秒間隔**（×2 でも 0.09秒）
  にして、1本ずつ数えられる刺さり方にした。フィニッシュは1本の槍（0.24秒）より長く（0.82秒）・大きく。
- **時間**（`src/dev/levi/leviTiming.ts`）：カットイン別で ×1 約3.1秒／×2 約2.4秒（各段に下限あり）。
- **位置**：実際の絵の位置を測って決める。レヴィは主人公の立ち位置（足元・体の中心）に、主人公の背丈で立つ。
  槍の穂先は必ず敵の手前で止まる（敵に重ならない。狭い画面では少し小さくして合わせる）。6本の槍は敵の絵の
  中心付近で交わり、穂先は中心の少し手前（敵が見える）。槍の長さは画面の端で切り詰め、浮かんでいる時も
  尾が大きく画面外に出ない。レヴィの絵は人の中（HUD の下）、槍・フィニッシュは魔法と同じ効果の層（HUD の上）。
- **出さないもの**：ダメージ数字・HP の変化・結果の1行・DEF/RESIST ▼ の表示（存在しない能力値）。
  戦闘の計算は一切呼ばない。再生中は戦闘の操作を受け付けない。終わると何も残らない。
- **部品**：`src/dev/levi/`（`LeviScene.tsx` 描画、`levi.css`、`leviTiming.ts`、`useLeviDirector.tsx`）。
  戦闘画面側には、場面を差し込む汎用の口 `BattleStage` の `scene`（`src/ui/battle/fieldScene.ts`）だけを
  足した（本編は何も渡さないので、本編の見た目・動きは変わらない）。レヴィの絵・部品・CSS は `src/dev/` にある
  ので、リリースビルドには入らない（`npm run check:release` で確認）。
- **DEBUGプレビュー**：「レヴィ『幻影槍6本』」欄に「▶ 幻影槍6本を再生」「先にカットイン：あり／なし」。
  押すたびに新しい戦闘で再生。チップに「直前のレヴィ ○.○○秒（×n）」。URL：`&levi=1`（カットインあり）、
  `&levi=bare`（なし）。
- **確認**：`src/dev/levi/leviTiming.test.ts`（6本・順番・同時にならない・×2 が短く下限以上）、
  `e2e/levi.spec.ts`（カットイン→登場→構え→6本出現→1本ずつ刺さる→フィニッシュ→退場の順、主人公が引いて戻る、
  数字・結果・HP変化なし、操作不可、何も残らない、×2、モスラビット／ガルド／小さい画面で位置、途中で止める、
  **本編では出ない**。動きを減らす設定でも同じ）。

## ケイオス魔法の演出と本編接続（STEP C、2026-09-26）

本編に実在するケイオスの魔法5つ（`content/magic/magicDefs.ts` の `MAGIC_DEFS`）すべてに、
1本の共通パイプラインで演出を付け、**本編の戦闘に接続した**。DEBUG プレビューも同じパイプライン。

- **流れ**（`battleTheatre.playSpell`）：魔法を選ぶ → 共通部分の `castMagic` が結果を一度に決める
  → ①カットイン（魔法の正式名称）→ ②詠唱（ケイオスの詠唱ポーズ＋オーラ）→ ③着弾／効果
  → ④本物の結果を反映 → ⑤敵の反撃（いつも通り）→ 次のターン。
  - **MP は行動が決まった時点（カットインの前）に減る**。魔法が**起こすこと**（HPバー・撃破・勝敗の進行）は
    ③の瞬間まで唱える前の状態のまま。これで「当たる前に敵が倒れる」「結果画面がカットイン中に出る」が起きない。
    （STEP B-3 で MP の減るタイミングを「行動確定→カットイン」の順に合わせた。）
  - **カットインの対応表**（`magic/spellCutIn.ts` の `SPELL_CUT_INS`、STEP B-3）

    | 魔法（id） | カットイン | 絵 | 長さ |
    |---|---|---|---|
    | 星光弾（starlight_bolt） | ケイオス | `characters/kaos/kaos-cast.png` | 通常技 |
    | 彗星撃（comet_strike） | ケイオス | 同上 | 必殺技 |
    | 癒しの光（mending_light） | ケイオス | 同上 | 通常技 |
    | 星盾（star_shield） | ケイオス | 同上 | 通常技 |
    | 星霞（star_haze） | ケイオス | 同上 | 通常技 |

    表に無い魔法は**カットインなし（未接続）**で、ほかの演出だけが流れる（誰かの絵を借りない）。
    v18 の「双極崩界」は本編の魔法ではないので表に入れず、プレビューの見本のまま残す。
  - カットイン再生中は画面全体が押下を受けないので、攻撃・魔法・スキル・アイテム・防御・×2（本編にない AUTO・
    逃走も同じ）で割り込めない。速度はそのまま。
  - 戦闘計算・技の数値・SAVE・WORLD MEMORY は変更していない。
- **魔法ごとの違い**（魔法データの `effect` と `animation` から決める。名前や id では決めない）

  | 魔法 | 種類 | カットイン | 着弾・効果 | 数字 |
  |---|---|---|---|---|
  | 星光弾 | 攻撃 | 通常技（1.4秒） | 敵の中心に小さな光輪と破片 | ダメージ（敵HPの減少量） |
  | 彗星撃 | 攻撃（大技） | **必殺技（2.5秒）** | 上から光が落ち、敵の中心で大きな爆光・二重の輪 | ダメージ（同上） |
  | 癒しの光 | 回復 | 通常技 | 主人公に緑金の光が立ちのぼる | なし（下の文で表示） |
  | 星盾 | 防御 | 通常技 | 主人公を包む光の膜 | なし |
  | 星霞 | 弱体 | 通常技 | 敵の目の前に星明かりの霞が流れる | なし |

  - 数字は攻撃魔法だけ。値は「唱える前の敵HP − 唱えた後の敵HP」（通常攻撃と同じ）。
  - 回復・防御・弱体には**数字を作らない**。何が起きたかは**共通部分の戦闘ログの結果文そのもの**
    （例「《癒しの光》！ HPが22回復した。」「《癒しの光》……HPはもう満ちている。」
    「《星霞》！ 敵の攻撃が鈍った。（4ターン）」）で出す。
  - **表示のしかた（STEP B-2 で変更）**：枠つきの大きい文字の板と雰囲気文（「ケイオスの手のひらから…」）は
    **出さない**。技名を含む結果文だけを、場所名の下に**枠なし・両端が消える薄い帯**で出す（`bp-told`）。
    STEP B-4 から2行：1行目に技名（「《星光弾》！」）、2行目に結果（「モスラビットに30のダメージ。」）。
    戦闘ログの文を技名の終わりで切るだけで、言葉は変えない（満タン時は「《癒しの光》」「……HPはもう満ちている。」）。
    3.2秒（×2 は 2.2秒）表示して消える。敵の攻撃が当たる間に上部 HUD が薄くなる演出の影響を受けない位置に置く。
    雰囲気文はカットインの下の行にだけ残る。アイテムの文字の板は従来どおり。
- **カットイン**：STEP B の部品をそのまま使用。名前は魔法データの `name`、下の行は同じく `line`、
  絵は `kaos-cast.png`、配色は v18 ケイオス。上の小さい行は「KAOS · STAR MAGIC」（データの属性・種別）。
  v18 の仮称（双極崩界など）は出さない。
- **詠唱と着弾の長さ**（`magic/spellShow.ts`。×2 でも下限あり）

  | | ×1 | ×2 |
  |---|---|---|
  | 詠唱（オーラ） | 0.82秒 | 0.48秒（下限） |
  | 着弾・効果 | 0.76秒 | 0.48秒（下限） |

  1回の魔法（反撃を除く）：通常技 約3.0秒／×2 約2.1秒、彗星撃 約4.1秒／×2 約2.8秒。
- **見た目**：v18「双極崩界」のオーラ（金と青の紋章輪・輪・光の粒）と「敵の中心で起きる」着弾を CSS で再現
  （`magic/spellfx.css`）。Canvas は使わない。演出は**レイヤー35（HUD の上、選択パネル・カットインの下）**。
  位置は、唱え始めた時の実際の絵（ケイオス・敵・主人公）の中心を測って合わせる（モスラビットでもガルドでも合う）。
- **入力**：演出中はコマンドを受け付けない（連打しても1ターン）。カットイン中は画面全体の押下も受けない。
- **補助修正**（必要最小限）：
  - 文字の板（`bp-said`）が1文字ずつ縦に折り返され、中央に縦長の暗い帯が出ていた（STEP A からアイテム使用時に
    発生していた不具合）。幅を与え、文字色を HUD の明るい色に（`battle.layers.css`）。

## カットイン部品（STEP B、2026-09-26）— 本編の魔法に接続済み（STEP C）

戦闘アニメ試作 v18 のカットインを、App で使い回せる独立部品として作り直したもの。
**本編の技・戦闘の流れには一切つないでいない**（本編の戦闘でカットインは出ない。テストで確認）。

- **部品**：`src/ui/battle/cutin/`
  - `CutIn.tsx`：`<CutIn>`（描くだけ）と `useCutInDirector(speed)`（`play(spec)` → 終わったら
    `'done'`／止めたら `'stopped'` を返す。`stop()` で即終了。画面が消えると自動で終了）。
    戦闘・WORLD・SAVE を読まず書かない。どの技かも知らない（技との対応づけは次の工程）。
  - `cutInTiming.ts`：表示時間（下表）。`cutInTiming.test.ts` が長さ・下限・読める時間を固定。
  - `cutin.css`：v18 の `.skill-cut-in` と4キャラ分の配色・配置を移植（`ci-` 接頭辞）。
- **表示時間**（フェードIN〜フェードOUT全体。技名が完全に見えるのは全体の17%〜88%＝71%）

  | 種類 | ×1 | ×2（下限） | 技名が読める時間 ×1 / ×2 |
  |---|---|---|---|
  | 通常技 | 1.4秒 | 1.1秒 | 約0.99秒 / 約0.78秒 |
  | 必殺技・大技 | 2.5秒 | 1.8秒 | 約1.78秒 / 約1.28秒 |

  必殺技は v18 アリアの修正済みの値そのまま。全カットインに v18 アリアの「読める」曲線（hold）を使う。
  ×2 は短くなるが下限より短くはならない。再生中に速度を変えても、そのカットインの長さは変わらない。
- **重なり順**：背景 → キャラクター → HUD・コマンド → （覚醒場面 30）→ 演出エフェクト（35、予約のみ）
  → 選択パネル（40）→ **カットイン（45）**。技名はカットインの一部として最前面に描く。
  再生中はカットインの層が押下を全部受けるので、下のコマンド・×2・BGM は押せない。
- **後に何も残さない**：カットインの DOM は再生中だけ存在し、終われば消える（戦闘画面に class も暗幕も
  タイマーも残らない）。カメラには触れない。入力ロックは「再生中かどうか」だけで決まる。
- **動きを減らす設定**のときは、動かさずに同じ時間だけ表示する（v18 と同じ）。
- **見本（v18 の4つ、プレビュー専用）**：`src/dev/cutInSamples.ts`。技名は v18 の**仮称**で、
  下の行に「仮称・v18 CUT-IN 見本（本編未接続）」と出す。v18 にあった能力値の変化の行
  （ATK/SPD/CRIT UP、DEF/RESIST DOWN）は本編に無い能力値なので載せていない。
- **使った素材**（すべて v18 の元ファイルのまま。加工・再圧縮なし）

  | 見本 | 画像 | 備考 |
  |---|---|---|
  | ケイオス | `characters/kaos/kaos-cast.png` | 既存（v18 と同一ファイル） |
  | 主人公 | `characters/hero/hero-battle-idle.png` | 既存（v18 と同一ファイル） |
  | レヴィ | `characters/levi/levi-battle.png` | v18 から追加（FILE_MANIFEST.sha256 と一致） |
  | アリア | `characters/aria/aria-cutin.png` | v18 から追加（同上） |

  レヴィ・アリアの画像はデバッグ用プレビューだけが使い、**リリース用ビルドには入らない**

## 戦闘演出プレビュー（デバッグビルド専用）

演出（今後のカットイン・魔法・スキル演出を含む）を、本編に繋ぐ前に確認するための独立画面。
`src/dev/BattlePreview.tsx`。

- **入れる所**：開発サーバー（`npx vite`）と **デバッグAPK**（CI の `npm run build:debug`、`.env.debug` の
  `VITE_MUGEN_DEBUG_TOOLS=1`）。**リリース用の `npm run build` には、この画面も入口も入らない**
  （ビルド時に削除）。`npm run check:release` が実際にリリース用ビルドを作って JS を検索し、
  入っていたら失敗する。この確認はデバッグAPKのCIでも毎回走る。
- **入口**：タイトル画面の左下「DEBUG 戦闘演出プレビュー」（デバッグビルドにだけ出る）。
  ブラウザでは `?preview=battle` でも開ける。
- **本編と同じ戦闘計算**：`playerAttack` / `playerDefend` / `castMagic` / `useItem`（共通部分）を
  そのまま呼ぶ。プレビュー専用の計算は無い。
- **世界には一切繋がない**：WORLD・SAVE・WORLD MEMORY・報酬・戦闘結果画面に触れない
  （開いてもセーブのデータベースを1つも開かないことをテストで確認）。勝っても負けても、その場で止まる。
- **固定条件で何度でも**：乱数は固定の並び。「もう一度（最初から）」で最初からやり直すと、
  同じ操作で同じ数字になる。敵の行動は「おまかせ／攻撃／技」に固定できる
  （共通部分にもともとある「敵の行動を指定する」引数を使用）。
- **画面上の DEBUG パネル**（上の中央、折りたたみ）：もう一度／敵（モスラビット・ガルド）／
  魔法の有無（ガルド戦は戦闘中に目覚める）／持ち物（全種1つずつ）／背景6種／敵の行動／タイトルへ戻る。
- **ケイオスの魔法**（同じパネル）：本編の5つの魔法それぞれのボタン。押すたびに新しい戦闘（MP満タン・
  同じ乱数・モスラビット）で1回唱える（本編と同じ処理・同じ演出）。「主人公のHP：半分から」で回復を確認できる。
  `&spell=mending_light` `&hurt=1` でも同じ。
- **カットイン**（同じパネル）：見本4つ（ケイオス・主人公・レヴィ・アリア）の単独再生／4つを連続再生／
  直前のカットインを再実行／長さ（見本どおり・通常技・必殺技）／速度 ×1・×2。再生中は上に
  「■ カットインを途中終了」が出る。チップに「直前のカットイン ○.○○秒（×n・種類）」を表示。
  `&cutin=aria` などで開いた直後に1つ再生。

## 作り

- **画面の部品はArtifactのファイルをそのままコピー**（`src/` からの相対パスも同じ）。
  `formation.ts`（立ち位置）、`battleCamera.ts`、`BattleHud.tsx`（左上・中央上・右上のパネル）、
  `battleHud.ts`、`battleMessage.ts`、`BattleIcons.tsx`、`stagecraft.ts`、`battleArcana.ts`、
  `CharacterArt.tsx`、`Ornament.tsx`。
  `src/ui/battle/artifactCopies.test.ts` が Artifact と1バイトでも違えば失敗する。
- **見た目（CSS）はArtifactのスタイルシートから機械的に抜き出し**
  （`scripts/port-battle-css.mjs` → `src/ui/battle/battle.generated.css`、2,242行）。
  戦闘のクラス（`bp-` / `bx-`）を使うルールと、それが使うアニメーションと配色だけ。
  配色は戦闘画面の中だけに効くようにしてあり、他のApp画面の色は変わらない。
  Artifact側が変わったら `node scripts/port-battle-css.mjs` を再実行（しないとテストが失敗）。
- **画面そのもの**は `src/ui/battle/BattleStage.tsx`。Artifactの `BattleUIPrototype` の
  描画部分と同じ構造・同じクラス名。**本物の戦闘状態（`BattleState`）を受け取って描くだけ**で、
  戦闘計算・ターン進行は一切しない。コマンドは押されたことを知らせるだけ（未接続の今は何も起きない）。
- **画像**は戦闘画面が使うファイルだけを1枚ずつ指定（`src/ui/battle/battleArt.ts`）。
  どの絵を出すかは共通部分の規則で決め、`battleArt.test.ts` がArtifactと同じファイル・
  同じ顔位置になることを確認する。
