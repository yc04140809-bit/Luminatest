# 装備画面 設計案 — MUGEN ZERO

未実装画面の優先順位 **1. 装備 → 2. スキル → 3. ストーリー** のうち、
最優先の装備画面の設計案です。**まだ1行も実装していません。**

---

## 0. 先に、正直な現状整理

設計の前に、**装備品というデータがこのゲームにまだ存在しません。**
これを曖昧にしたまま画面だけ作ると、仮のアイテムを捏造することになります。

### あるもの

| | 実体 | 場所 |
|---|---|---|
| **武器種** | `LONG_SWORD` / `DUAL_DAGGER` / `SPEAR` / `BOW` | `WEAPON_CANON` |
| 戦闘スタイル | `SWORDSMANSHIP` / `MAGIC` | `battleProfiles.ts` |
| 持ち物 | `ItemDef`（内容）と `ItemStack`（セーブ） | `items.ts` |
| 道具の分類 | `CONSUMABLE` / `MATERIAL` / `KEY_ITEM` / `OTHER` | 同上 |
| お金と店 | LUMI、購入・売却 | `shop.ts` |
| 武器種→効果音 | `attackSfxFor()` | `weaponSfx.ts` |

### ないもの

- **装備品のデータそのもの**（剣も、鎧も、装飾品も、1つもありません）
- **装備スロット**という概念
- **防御力・魔力・素早さ**。`PartyStats` は `maxHp` / `maxMp` /
  `attackMin` / `attackMax` の4つだけです
- 装備が戦闘に影響する経路

つまり装備画面は「既存データを並べる画面」ではなく、
**新しいシステムを1つ足す**話です。

## 1. 導線

```
HOME →（ステータス）→ ステータス画面
                         ├ 左メニュー「装備」→ 装備画面
                         └ 左メニュー「ステータス」←（装備画面から戻る）
```

**ステータス画面の左メニューをそのまま使います。**新しいボタンは足しません。
現在は押せない表示になっている「装備」に、遷移と枠が**同時に**付きます。
「押せるように見えるが押せない」期間を作らないための設計です。

- 上部のキャラクター切替タブは**共通**。装備画面でも同じ2人を切り替えます
- 右側のメインビジュアルも**共通**。装備を変えても立ち絵は変わりません（後述）
- 戻り先は **HOME ではなくステータス画面**。左メニューは画面ではなくタブとして
  振る舞うべきで、HOMEへ飛ばすと「どこにいたか」が失われます
- Android の戻るボタンは `androidBack.ts` の表に1行追加するだけです

## 1-2. ワイヤー（実画面として描画したもの）

`docs/` には置けないので、実機と同じ 762×321 で描いた3枚を別送しています。

| 状態 | 内容 |
|---|---|
| 主人公・通常 | 武器枠1つ＋将来枠3つ（薄）＋説明文 |
| 主人公・武器選択中 | 説明文と**入れ替わって**所持武器一覧が出る |
| ケイオス | 武器枠が**そもそも無い**（武器種未確定のため） |

ステータス画面と**同じ骨格・同じ配色・同じ書体・同じ立ち絵領域**です。
違うのは左メニューの選択位置と、中央の中身だけです。

### 将来枠の見せ方

衣装・アクセサリ1・アクセサリ2 は**薄く表示**しますが、
**枠線も背景も持たせません**。押せる見た目にしないための線引きで、
ステータス画面の左メニューと同じ扱いです。

### 所持武器一覧

武器枠を押すと、説明文の位置に**入れ替わりで**出ます。別画面にしないのは、
「今どの武器で、何に替えられるか」を同時に見せたいからです。
一覧は**武器種で絞り込み済み**なので、装備できないものは並びません。

## 2. データ構造案

既存の `ItemDef` / `ItemStack` の分割と、`CharacterAppearance` /
`SkinDefinition` の分割に**そろえます**。同じ理由で同じ形にするのが、
この先いちばん壊れにくい形です。

```ts
/** どこに着けるか。増やすなら、ここだけを増やす。 */
type EquipmentSlot = 'WEAPON' | 'OUTFIT' | 'ACCESSORY_1' | 'ACCESSORY_2';

/** v0.1 で操作できるのは武器だけ。他は枠だけ先に存在する。 */
const OPERABLE_SLOTS: readonly EquipmentSlot[] = ['WEAPON'];

/** 装備品が何であるか。ビルドに入る。セーブには絶対に入らない。 */
interface EquipmentDef {
  equipmentId: string;
  name: string;
  slot: EquipmentSlot;
  description: string;
  sellPrice: number;
}

/**
 * 武器。`EquipmentDef` を狭めた別の型にします。
 *
 * `weaponType` は武器なら必ずあり、防具にはありません。1つの型に
 * 省略可能で持たせると「武器種の無い武器」が型の上で作れてしまい、
 * それを弾くコードが各所に散ります。
 */
interface WeaponDefinition extends EquipmentDef {
  slot: 'WEAPON';
  /** ここが武器種 CANON と繋がる唯一の点。 */
  weaponType: WeaponType;
  /**
   * 攻撃力補正。**§4 の決定が出るまで 0 のみ**。
   * 表示する以上は戦闘に効かせます。効かせないのに表示するのは嘘です。
   */
  attackBonus: number;
}

/** 持っている装備。セーブに入るのは id と個数だけ。 */
interface OwnedEquipment {
  equipmentId: string;
  quantity: number;
}

/** 誰が何を着けているか。セーブに入りうる唯一の部分。 */
interface CharacterEquipment {
  characterId: string;
  /** 未装備は null。「無し」という選択であって、欠落ではない。 */
  equipped: Partial<Record<EquipmentSlot, string | null>>;
}
```

### なぜ `weaponType` が装備品側にあるのか

**武器種を「持っているもの」から決められるようになるためです。**

現在、主人公の武器種は `WEAPON_CANON.hero = 'LONG_SWORD'` 固定です。
装備品が `weaponType` を持てば、

```
装備中の武器 → その武器の weaponType → attackSfxFor() → 攻撃音
                                     → ステータス画面の「武器種」表示
```

と繋がり、**武器を持ち替えると攻撃音と表示が自動で変わります。**
効果音の仕組み（`weaponSfx.ts`）は既にこの形で作ってあるので、
装備側が `weaponType` を答えるようになるだけで繋がります。

`WEAPON_CANON` は**残します**。何も装備していないとき、レヴィやアリアの
ように本体が未実装のとき、そして装備システムを持たない mugen-artifact の
ために、「素のその人が何を使うか」は必要です。解決順は
**装備 → 無ければ CANON** です。

### 装備できる武器の制限

キャラクターは **自分の武器種の武器しか装備できません。**

```
主人公（LONG_SWORD）は長剣だけ
ケイオス（武器種 null・MAGIC）は物理武器を装備できない
```

これで武器種 CANON が「表示用の設定」から「ルール」になります。
ケイオスの物理武器が未確定なのは**未決定であって、空欄ではない**ので、
この制限のもとでは彼女の武器スロットは**そもそも存在しません**
（「装備なし」と表示するのではなく、スロットを描きません）。

## 3. 画面の構成案

ステータス画面と同じ骨格（左メニュー / 中央 / 右ビジュアル）を保ちます。
アイボリー＋金＋明朝もそのままです。

```
┌ STATUS ─┬─────────────────────────┬──────────┐
│ ステータス │  [主人公] [ケイオス]      │          │
│ 装備 ◀   │                          │  立ち絵   │
│ スキル   │  ■ 武器    長剣           │ （共通）  │
│ ストーリー │      ○○の剣             │          │
│         │  ■ 防具    －未実装－      │          │
│         │  ■ 装飾    －未実装－      │          │
│         │                          │          │
│         │  ── 持ち替え候補 ──        │          │
│         │  ○○の剣  ／  △△の剣      │          │
│ もどる   │                          │          │
└─────────┴─────────────────────────┴──────────┘
```

**未実装のスロットは行ごと描きません**（「－未実装－」は上の図の説明用で、
実装では出しません）。防具と装飾は、そのデータが作られた日に現れます。

左は選択中のスロット、右下は**そのスロットに着けられる候補**。
候補は持ち物から武器種で絞り込まれるので、「装備できないものが並ぶ」
ことがありません。

## 4. 戦闘への影響 — **ここが作者の判断事項です**

「戦闘バランスは変更しません」という前提があるため、
`EquipmentEffect` の中身は**勝手に決められません。**3案あります。

### A案：効果なし（バランス完全無変更）

装備は**見た目と武器種だけ**を変え、数値には一切影響しません。

- 長剣を持ち替えると、攻撃音と「武器種」表示が変わる
- HP・MP・攻撃力は変わらない
- **バランス変更ゼロ。SAVE schema 変更ゼロ。今すぐ作れます**
- ただし「強くなる装備」が欲しい場合は不足です

### B案：攻撃力の幅だけを動かす

`attackMin` / `attackMax` に加算します。既存のステータスだけを使うので、
**新しい能力値を作りません**。

- 影響範囲は `statsForLevels` の1か所
- レベル曲線との兼ね合いを決める必要があります（レベル10相当の武器とは？）
- **これはバランス変更です。承認をいただいてから着手します**

### C案：防御力・魔力を新設する

参考画像にあった 防御力 / 魔力 / 素早さ を実際に作ります。

- `PartyStats` の拡張、戦闘計算式の変更、敵側の数値の再設計が必要
- 影響範囲が最大で、**別ラウンド相当の規模**です
- ステータス画面に 防御力・魔力 の行が復活します

**推薦は A案からの段階導入**です。A案は今の制約の中で完結し、
B案・C案はその上に載せられます。逆順はできません。

## 5. SAVE 互換性

**schema のバージョン変更は不要です。**

`saveSchema.ts` の規約どおり、`world_state` に行を1本足すだけで済みます。

> 「A missing field is not a migration… a save from before a feature
> existed needs no step at all」

- 新しい行は2本：
  - `character_equipment`（キャラID → スロット → 装備品ID）
  - `owned_equipment`（所持している装備品のIDと個数）
- 既存セーブにはどちらの行も無く、それは**全スロット未装備・所持ゼロ**
  として読まれます
- 装備品IDがビルドから消えた場合は**未装備に戻し**、画面を失わせません
- **装備品の性能はセーブに入りません。**`EquipmentDef` はビルド側なので、
  剣の攻撃力を後から変えても既存セーブは全部正しいままです
  （`ItemDef` の値段と同じ理屈です）

命名機能のときと同じく、**実装前にこの見取り図を出すのが先**です。

## 6. スキン拡張との関係

**装備とスキンは別物として保ちます。**

| | 変えるもの | 変えないもの |
|---|---|---|
| 装備 | 武器種、（B/C案なら）能力 | 見た目 |
| スキン | 見た目だけ | 能力・武器種・物語 |

装備を変えても**立ち絵は変わりません**。ステータス画面専用ビジュアルは
背景込みの1枚絵で、武器を持ち替えるたびに描き直すことはできないからです。

将来、装備が見た目に出るとしたら、それは
`SkinAssetRefs` に武器差分を足す話であり、`EquipmentDef` に画像を
持たせる話ではありません。**スキンに数値を持たせないのと同じ理由で、
装備に見た目を持たせません。**

## 7. 作業単位の分割案

| # | 内容 | バランス変更 | SAVE変更 | 前提 |
|---|---|---|---|---|
| 1 | 型（`EquipmentSlot` / `EquipmentDef` / `WeaponDefinition` / `CharacterEquipment` / `OwnedEquipment`）と解決関数 | なし | なし | — |
| 2 | 装備画面のUI・導線・左メニューの有効化・キャラ切替 | なし | なし | 1 |
| 3 | 武器種の解決を「装備 → CANON」の順に | なし | なし | 1 |
| 4 | 装備と所持の保存・復元 | なし | 行2本追加（version据え置き） | 1 |
| 5 | 最初の武器データ | **補正0なら無し** | なし | **作者の決定待ち** |
| 6 | 攻撃力補正を戦闘に効かせる | **あり** | なし | **要承認** |

**1〜4 は今すぐ着手できます。** 5 は「どんな武器が世界にあるか」という
作者の決定が要り、6 は承認が要ります。

ご指示の優先順位（1.武器表示 → 2.武器変更 → 3.保存 → 4.キャラ切替 →
5.立ち絵領域）は、上の 1〜4 に含まれています。立ち絵領域はステータス
画面のものを**そのまま使う**ので、新規実装はありません。

## 8. 決めていただきたいこと

1. **効果の方針** — A案（効果なし）／B案（攻撃力のみ）／C案（能力値新設）
2. **最初の武器** — 名前・説明・入手方法。数点で足ります。
   こちらでは作りません（捏造になるため）
3. **防具・装飾を作るか** — 当面は武器スロットだけでも成立します
4. **入手経路** — 店で買う／敵が落とす／物語で手に入る

1 と 2 が決まれば、1〜5 をまとめて実装できます。
